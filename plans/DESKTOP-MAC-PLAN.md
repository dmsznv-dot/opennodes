# OpenNodes для macOS — план (без подписи; сервер — позже, но заложен сразу)

_Дата: 2026-11-05. Статус: план, не начато._

## 1. Цель

Обычное приложение для Mac: скачал `.dmg`, перетащил в «Программы», открыл — и работаешь в
редакторе в собственном окне, без терминала, браузера, Docker и Postgres. Сценарии
выполняются на этом же Mac, данные хранятся у пользователя.

Сервер сейчас не делаем, но приложение сразу устроено так, чтобы позже подключить его без
переделок: одно место решает, откуда берётся OpenNodes — встроенный на этом Mac или на
сервере (раздел 3.1).

## 2. Что входит и что нет

**Входит**

- Приложение `OpenNodes.app` для Apple Silicon (arm64); сборка для Intel — по желанию.
- Встроенный сервер, как сейчас в `pnpm start:local`: API в режиме `embedded`, база PGlite
  в папке приложения, очередь в том же процессе.
- Окно с редактором, нативное меню macOS, значок в строке меню, работа в фоне.
- Установщик `.dmg` с новой иконкой.

**Не входит (позже)**

- Подпись и нотаризация Apple. Без них при первом запуске macOS предупреждает «разработчик
  не проверен» (как открыть — раздел 7).
- Автообновления: без подписи macOS их не пропускает. Новая версия — новый `.dmg`.
- Само подключение к удалённому серверу. Заготовка под него входит (раздел 3.1, этап 1),
  а экран «Подключиться к серверу» и перенос данных — следующий план.
- Windows.

## 3. Как устроено

```
OpenNodes.app
├─ Electron, главный процесс (main.js)
│   ├─ выбирает два свободных порта на 127.0.0.1
│   ├─ запускает API   (apps/api,  EXECUTION_MODE=embedded, DATABASE_URL=pglite://<данные>/pglite)
│   ├─ запускает Web   (apps/web — раздаёт docs/ и проксирует /api)
│   ├─ ждёт /health, затем открывает окно
│   └─ значок в строке меню, меню приложения, выход
└─ Окно (BrowserWindow) → http://127.0.0.1:<webPort>  — тот же редактор, что сейчас
```

- **Как запускать сервер.** Те же `apps/api/dist/index.js` и `apps/web/dist/server.js`.
  Дочерние процессы получают Node, встроенный в Electron:
  `process.execPath` + `ELECTRON_RUN_AS_NODE=1`. Сначала берём готовый код `start-local.mjs`
  и выносим его в общую функцию, чтобы терминал и приложение запускали сервер одинаково.
- **Данные:** `~/Library/Application Support/OpenNodes/` (папка `pglite/`, ключ шифрования).
- **Логи:** `~/Library/Logs/OpenNodes/` (api.log, web.log, main.log).
- **Ключ шифрования подключений** хранится не открытым файлом, а зашифрованным через
  `safeStorage` Electron — это связка ключей macOS (Keychain).
- **Порты:** свободные, а не 3000/4000, чтобы не мешать другим программам. Слушаем только
  `127.0.0.1`.

### 3.1. Заготовка под сервер

Редактор уже умеет работать с любым API: адрес берётся из `config.js`, а сервер в Docker
сам раздаёт тот же редактор. Значит, приложению для работы с сервером нужно только открыть
окно на другом адресе. Чтобы это потом было одной правкой, а не переделкой, сразу делаем так:

- **Один интерфейс «откуда берётся OpenNodes»** (`backend`) с методами `start()`,
  `stop()`, `url`, `health()`. Сейчас есть одна реализация — `LocalBackend` (встроенный
  сервер). Позже добавится `RemoteBackend` (адрес сервера и проверка `/health`). Окно,
  меню, значок в строке меню и уведомления работают с интерфейсом и не знают, какой он.
- **Настройки приложения** (`settings.json` в папке данных) сразу хранят
  `{ "mode": "local", "remoteUrl": null }`. Сейчас `mode` всегда `local`; поле нужно,
  чтобы переключение потом не меняло формат файла.
- **Вход как на сервере.** Во встроенном режиме тот же экран создания владельца и входа,
  что на сервере, — без особого «режима без пароля». Тогда при переходе на сервер
  пользователь ничего нового не увидит.
- **Перенос данных — через API.** Экспорта и импорта сценариев в OpenNodes пока нет — их
  сделаем вместе с подключением к серверу, через API, а не копированием папки PGlite. Тогда
  перенос сработает и «с Mac на сервер», и обратно. Секреты подключений не переносятся: на
  сервере их вводят заново, это безопасно. Сейчас для этого ничего делать не нужно.
- **Уведомления и счётчики** в строке меню читают состояние через API (`/executions`,
  список сценариев), а не из базы напрямую — для сервера ничего не меняется.
- **Один бот — одна копия OpenNodes.** Когда появится сервер, при переключении
  предупреждаем: Telegram-боты, активные на Mac, нужно выключить там, где они больше
  не нужны.

## 4. Этапы

### Этап 0. Подготовка (0,5 дня)

- [ ] Пакет `apps/desktop` в монорепо (Electron, electron-builder).
- [ ] Логику запуска из `scripts/start-local.mjs` вынести в `scripts/local-server.mjs`: функция
      `startLocal({ dataDir, apiPort, webPort, encryptionKey, log })`. `start-local.mjs`
      вызывает её же — поведение в терминале не меняется.
- [ ] Проверить, что PGlite (WASM) и все зависимости API работают под Node из Electron (нет
      нативных модулей; Redis и BullMQ в режиме `embedded` не нужны).

**Готово, когда:** `pnpm start:local` работает как раньше, а `startLocal()` поднимает сервер из
отдельного скрипта.

### Этап 1. Окно приложения (1 день)

- [ ] `main.js`: блокировка второго экземпляра (повторный запуск показывает уже открытое
      окно), выбор портов, запуск сервера, ожидание `/health` (до 30 с), затем окно.
- [ ] Экран загрузки «Запускаем OpenNodes…», пока сервер поднимается; понятная ошибка, если
      не поднялся (с кнопкой «Открыть логи»).
- [ ] `BrowserWindow`: `contextIsolation: true`, `sandbox: true`, без `nodeIntegration`.
      Переходы только на свой `127.0.0.1:<порт>`; внешние ссылки (Telegram, статьи)
      открываются в браузере по умолчанию (`shell.openExternal`).
- [ ] Заголовок окна в стиле macOS (`titleBarStyle: 'hiddenInset'`). Шапке редактора нужен
      отступ под «светофор» — класс `is-desktop` на `<html>` и пара строк CSS.
- [ ] Окно запоминает размер и положение.
- [ ] Интерфейс `backend` и `LocalBackend` (раздел 3.1); `settings.json` с полем `mode`.
      В меню «OpenNodes» пункт «Подключиться к серверу…» — пока неактивный, с подписью «скоро».

**Готово, когда:** приложение открывает редактор в окне, всё работает как в браузере, данные
сохраняются между запусками. Окно и меню обращаются к серверу только через `backend`.

### Этап 2. Как в нативном приложении (1 день)

- [ ] Меню macOS: «OpenNodes» (О программе, Настройки…, Скрыть, Выйти), «Правка»
      (Отменить, Вырезать, Копировать, Вставить, Выделить всё — без этого не работают
      ⌘C/⌘V), «Вид» (Перезагрузить, Масштаб, Полный экран), «Окно», «Справка» (Открыть
      папку данных, Открыть логи).
- [ ] Значок в строке меню: «Открыть OpenNodes», «Активных сценариев: N», «Запускать при
      входе в систему», «Выйти».
- [ ] Закрытие окна не останавливает сценарии: приложение остаётся в строке меню, как
      Telegram или Docker Desktop. ⌘Q останавливает сервер и выходит.
- [ ] Перед выходом при активных сценариях — вопрос: «Сценарии перестанут выполняться. Выйти?»
- [ ] Запрет сна, пока есть активные сценарии с расписанием (`powerSaveBlocker`
      `prevent-app-suspension`), — как переключатель в меню, по умолчанию выключен.
- [ ] Уведомления macOS: сценарий упал; ждёт утверждения (по клику — «История»).

**Готово, когда:** приложение ведёт себя как обычное для Mac — копирование и вставка работают,
закрытие окна не останавливает сценарии, выход только явный.

### Этап 3. Сборка `.dmg` (0,5–1 день)

- [ ] Иконка `.icns` из `assets/icon-1024.png` (`iconutil`, все размеры 16–1024, @2x).
- [ ] electron-builder: `mac.target = dmg`, `arch = arm64` (+ `x64` по желанию),
      `identity: null` (без подписи), фон `.dmg` со стрелкой «перетащите в Программы».
- [ ] В приложение кладём `apps/api/dist`, `apps/web/dist`, `docs/` и только рабочие
      зависимости. С ссылками pnpm workspace electron-builder дружит плохо, поэтому либо
      `pnpm deploy --prod` в отдельную папку, либо сборка API и Web в два файла через
      esbuild (WASM-файлы PGlite скопировать рядом). Выбрать по итогам этапа 0.
- [ ] Скрипт `pnpm desktop:build` → `apps/desktop/dist/OpenNodes-<версия>-arm64.dmg`.
- [ ] Размер: цель — до ~150 МБ (Electron около 100 МБ плюс наш код).

**Готово, когда:** `.dmg` собирается одной командой, устанавливается и запускается на чистом Mac
без установленных Node, pnpm и Docker.

### Этап 4. Проверка (0,5 дня)

- [ ] Первый запуск на чистой учётной записи macOS: предупреждение Gatekeeper и открытие
      по инструкции из раздела 7.
- [ ] Создать владельца, подключение Telegram-бота и ИИ, собрать сценарий
      «RSS → ИИ → Telegram», проверить, включить.
- [ ] Закрыть окно — сценарий по расписанию продолжает выполняться.
- [ ] ⌘Q и повторный запуск — сценарии и подключения на месте, ключи расшифровываются.
- [ ] Второй запуск, пока приложение открыто, — открывается то же окно, второй сервер не стартует.
- [ ] Занятые порты 3000/4000 (запущен `pnpm start:local`) — приложение всё равно работает.
- [ ] Сервер не поднялся (например, папка данных недоступна для записи) — понятная ошибка
      и путь к логам.
- [ ] Копирование и вставка, ⌘Z на холсте, правый клик, тёмная тема.
- [ ] Резервная копия: «Справка → Открыть папку данных» + `pnpm backup` для этой папки.

## 5. Ограничения, о которых говорим пользователю

- Сценарии выполняются, только пока приложение запущено и Mac не спит. Для круглосуточной
  работы нужен сервер (Docker) — это следующий шаг.
- Telegram-боты в приложении и на сервере одновременно конфликтуют: одним ботом может
  управлять только одна копия OpenNodes.
- Обновление — скачать новый `.dmg` и заменить приложение; данные остаются в
  `~/Library/Application Support/OpenNodes`.

## 6. Риски

| Риск                                                        | Что делаем                                                             |
| ----------------------------------------------------------- | ---------------------------------------------------------------------- |
| PGlite или зависимость не работает под Node из Electron     | Проверяем на этапе 0 до остальной работы                               |
| pnpm workspace плохо упаковывается                          | `pnpm deploy --prod` или esbuild-бандл (этап 3)                        |
| Старт дольше пары секунд (миграции PGlite)                  | Экран загрузки; миграции только при смене версии                       |
| Пользователь закрыл окно и думает, что приложение выключено | Значок в строке меню, уведомление при первом закрытии окна             |
| Без подписи macOS блокирует запуск                          | Инструкция в README и на странице загрузки; подпись — отдельным этапом |

## 7. Как открыть неподписанное приложение

1. Перетащить `OpenNodes.app` в «Программы».
2. Первый раз: правый клик по приложению → «Открыть» → «Открыть» в окне предупреждения.
   На macOS 15 и новее: «Системные настройки → Конфиденциальность и безопасность» →
   «Всё равно открыть».
3. Или в Терминале: `xattr -dr com.apple.quarantine /Applications/OpenNodes.app`.
