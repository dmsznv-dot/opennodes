# Fields and UI wording review — 2026-11-03

## 1. Does every field do something?

`apps/api/tests/fields.test.ts` runs every step of the catalog against local stand-ins
(Telegram, an OpenAI-compatible model, Ollama, Discord/Slack webhooks, HTTP echo, SMTP, RSS).
Each field gets a unique marker, and the marker must show up in what the step sends out or
in what it hands to the next step. Fields whose effect leaves no marker are listed in the
test with what they do instead (for example “None” formatting sends no `parse_mode`).

| Step | Problem found | Fix |
|---|---|---|
| Webhook / form (trigger) | “Receiving path” and “Verify HMAC signature” were ignored: the server address is always `/api/v1/webhooks/<id>`, and the signature is set via the API (`webhookSecret`) | Fields removed. The step shows the real address in the installed app, and an explanation in the demo |
| Webhook / form (trigger) | “+ Data” offered only name, email, message and budget, but a form can send any fields | Fields that arrived in the latest run are offered too. “Another form field…” inserts any field by its name |
| AI: answer / AI: classify | The model was a required choice of three OpenAI names. A local model (LM Studio, Ollama) got `gpt-4o-mini`, and the connection’s model was never used | Model is now an optional text field. Empty means the connection’s default model |
| AI: answer | The server supports a system prompt, but the editor had no field for it | Added “Role and style” (in Advanced) |
| Telegram message (trigger) | The server gives command, args, @username and message ID, but the editor offered only text, name and chat | All of them are offered. “Sender chat” is now “Chat ID (where to reply)” |
| Continue only if… | “Compare with” could not take data from another step | “+ Data” added |
| Local model (Ollama) | Default address `http://ollama:11434` only works inside Docker with an `ollama` service | Default is `http://localhost:11434`, with help for Docker and `SSRF_ALLOWLIST` |
| Payments template | Asked to “turn on signature verification”, which the editor cannot do | Text says how to set the signature through the API |

The data hand-off between steps is covered by `audit.test.ts` (70 scenarios). One more check
there: every output a step promises in the editor really is in its output on the server.

## 2. UI wording and logic

| Where | Problem | Fix |
|---|---|---|
| Everywhere (RU) | Both “автоматизация” and “сценарий” for the same thing: “Мои автоматизации”, “Открыть сценарий”, the status “Включена” next to “Сценарий включён” | Everywhere “сценарий”. Statuses are “Включён” / “Выключен” |
| Everywhere (RU) | “AI” and “ИИ” mixed | Russian texts say “ИИ” (OpenAI and API names stay as they are) |
| Step panel | “Тестировать шаг” next to “Проверить” in the header | “Проверить шаг” |
| AI: answer | “What to do with the text”, but there is no field for the text | “Task for the AI”, with help: say what to do and insert the data with “+ Data” |
| AI: process, AI agent | Placeholders in the old token format `{Шаг 2: …}`, which the editor no longer shows | Plain-language placeholders |
| HTTP request, outgoing webhook | The address field was labelled just “URL” | “Request URL” / “Webhook URL” |
| Text: process | “Find”, “Replace with”, “Pattern” and “N characters” were shown for every operation | Each one is shown only for the operation it belongs to |
| HTTP request | “Request body” was shown for GET | Shown only for POST, PUT, PATCH and DELETE |
| Schedule | “Time” was shown for “every 15 minutes” | Shown for daily and weekly only, with help “in the chosen time zone” |
| AI: process | “How many links to read” was shown with link reading off | Shown only when link reading is on |
| RSS | Help said tests never use items up, which the new switch contradicts | Help rewritten |
| Data picker | Block titles came out as “with heading «имя из формы»” (whole label lowercased) | Only the first letter is lowercased |
| Schedule | “Run time” is an ISO time in UTC, which looks like a technical value | Label says “UTC, for programs”. Readable dates are in “Date and time” |

## 3. Left as they are, worth doing later

- HTTP request: the response body is one JSON value. A field inside it (`body.data.items.0.name`) can only be typed by hand.
- JSON fields (outgoing webhook payload, HTTP body) have no “+ Data”. Tags can be typed by hand inside strings.
- Webhook signature (HMAC) can only be set through the API, not in the editor.
