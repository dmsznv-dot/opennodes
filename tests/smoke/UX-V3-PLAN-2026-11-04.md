# OpenNodes — план по UX v3: исследование, названия, порядок работ

Основа: `OpenNodes_UX_Workflow_Improvements_v3.md` (4 ноября 2026). Код не менялся — это предложение на согласование.

## 1. Как это сделано у конкурентов

| | Что хорошо | Что плохо |
|---|---|---|
| **Make** | После запуска над каждым модулем — кружок с числом операций; клик открывает входные и выходные данные каждого прохода ([помощь Make](https://make.com/en/help/scenarios/scenario-editor), [операции](https://help.make.com/operations.md)). Сразу видно, сколько раз шаг сработал и с какими данными | Термины «bundle», «operation», «iterator» новичку непонятны; по отзывам на G2 — крутая кривая обучения |
| **n8n** | Входные данные, настройки и результат шага видны рядом — пользователи прямо просят это сохранить ([форум n8n](https://community.n8n.io/t/help-us-test-some-canvas-improvements/201703)) | В списке нод не видно, что нода принимает и отдаёт — её приходится добавить, чтобы понять ([запрос на форуме](https://community.n8n.io/t/feature-suggestion-display-connector-types-in-the-open-nodes-panel/258791)); ошибки — большие блоки в углу экрана; новички ждут «магии» и не понимают, как текут данные |
| **Zapier** | Шаги называются «Приложение · Событие», любой шаг можно переименовать своими словами ([Zapier](https://zapier.com/blog/updates/835/editor-upgrades-add-notes-zaps-and-rename-any-step)); выбранные данные — плашки с иконкой и номером шага | Новички путают «значение из прошлого шага» и «написанное вручную»; пример данных расходится с живыми ([сообщество Zapier](https://community.zapier.com/how-do-i-3/importance-of-mapping-fields-19455)) |

**Выводы для OpenNodes**
1. Шаг называется **задачей человека**, а не механизмом: «Опубликовать в Telegram», а не «core.telegramBot» и не «Отправить сообщение через Bot API».
2. После проверки или запуска **число и результат — прямо на карточке**, как кружок у Make, но словами: «3 записи», «3 поста отправлено».
3. **Что шаг берёт и что отдаёт — видно до добавления**: в меню добавления под названием одна строка «Нужно: … · Даёт: …».
4. Никаких «bundle / operation / payload / items» в обычном режиме.

## 2. Новые названия шагов (русский — по смыслу, не дословно)

Правило: название отвечает на вопрос «что сделать?», в описании — **когда брать именно этот шаг**, чтобы не было выбора между похожими.

### Группы в меню добавления
| Сейчас | Предлагаю |
|---|---|
| Когда… | **С чего начинается** |
| Сделать | **Действия** |
| Логика | **Условия и обработка текста** |
| Для разработчиков | Для разработчиков (без изменений) |

### С чего начинается
| Сейчас | Предлагаю | Описание: когда брать |
|---|---|---|
| Запуск вручную с тестовыми данными | **Запуск вручную** | Чтобы проверить сценарий кнопкой «Проверить». Сам не запускается |
| По расписанию | По расписанию | Каждый день в 10:00, каждый час… |
| Новое сообщение в Telegram | **Боту написали в Telegram** | Когда нужно отвечать людям, которые пишут вашему боту |
| Отправлена форма / входящий вебхук | **Пришла заявка с сайта** | Форма на сайте, Tilda, сервис оплаты — всё, что умеет отправить данные на адрес |

### ИИ — главный источник путаницы
| Сейчас | Предлагаю | Описание: когда брать |
|---|---|---|
| ИИ: обработать данные по инструкции | **ИИ: переписать текст** | Перевести, пересказать, сократить, переписать в другом стиле. Для постов из статей — этот |
| ИИ: ответить на текст | **ИИ: ответить человеку** | Ответ на вопрос клиента или сообщение в боте |
| ИИ: определить категорию | **ИИ: определить тему** | «Вопрос / Жалоба / Заказ» — чтобы дальше направить по-разному |
| ИИ-агент с инструментами (MCP) | **ИИ-помощник с доступом к сервисам** | Сам создаёт документ, задачу, запись в Notion/GitHub через подключённые сервисы |
| Локальная модель: ответить на текст | **ИИ на своём компьютере (Ollama)** | То же, что «ответить человеку», но модель работает у вас |

### Действия
| Сейчас | Предлагаю | Описание |
|---|---|---|
| Получить новые записи RSS | **Новые статьи с сайта (RSS)** | Свежие публикации блога или СМИ; каждая приходит один раз |
| Отправить сообщение в Telegram | **Опубликовать в Telegram** | Пост в канал или сообщение в чат, с картинкой |
| Отправить фото или файл в Telegram | **Отправить файл в Telegram** | PDF, документ или фото без поста |
| Отправить письмо | Отправить письмо | — |
| Отправить сообщение в Slack / Discord | **Написать в Slack / в Discord** | — |
| Отправить данные на вебхук | **Передать данные в другой сервис** | Отправить данные на адрес другого сервиса (вебхук) |
| HTTP-запрос к API | **Запрос к API** (в «Для разработчиков») | — |
| Выполнить SQL-запрос | **База данных: SQL-запрос** (в «Для разработчиков») | — |

### Условия и обработка текста
| Сейчас | Предлагаю |
|---|---|
| Продолжить, только если… | без изменений |
| Подождать | без изменений |
| Текст: обработать | **Очистить или сократить текст** |
| Собрать текст или отчёт | **Собрать текст из данных** |

Внутренние типы шагов (`ai.process` и т. д.) не меняются — сохранённые сценарии работают как раньше.

Свободный холст, масштаб, Fit, Undo/Redo, вставка в связь одним Undo, быстрое меню с клавиатурой, цветные теги, понятные подписи данных, скрытые технические поля, контекстные поля (тело запроса только для POST и т. п.), «для каждой записи» с лимитом.

## 4. Порядок работ

**Шаг 1 — названия (из раздела 2).** Небольшой объём, сразу снимает вопрос «какую ноду добавить». Плюс строка «Нужно: … · Даёт: …» в меню добавления.

**Шаг 2 — карточка шага (раздел 4 документа, P0).** На карточке: название, одна строка сути («Канал @fwcreate · по записи»), статус словами, а после проверки — результат: «3 записи», «3 поста отправлено», «ошибка: у бота нет прав в канале». Для неполной настройки — кнопка действия: «Подключить бота». ID и технические данные — только в режиме разработчика.

**Шаг 3 — ошибки и данные на графе (раздел 10, P0).** Клик по карточке после проверки — «Получил / Отдал / Ошибка» человеческими словами; ошибки Telegram, ИИ и RSS переводятся в понятные причины с подсказкой, что сделать.

**Шаг 4 — жесты (раздел 6).** Документ предлагает: **клик по пустому месту — снять выделение, двойной клик — меню добавления**. Сейчас одиночный клик открывает меню — это противоречит документу, нужно ваше решение.

Дальше (P1): режим «Шаги / Схема», группы, многовыделение, auto-layout, мини-карта, вложенный JSON — после шагов 1–4.
